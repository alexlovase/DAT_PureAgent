# DAT Agent Review V1：初版执行方案

日期：2026-10-14
状态：设计建议；已核对公开 Skills / harness 文档及项目远端入口，未实施代码、安装 Skills、验证真实板卡准确率或修改远端。

## 1. 定位与目标

初版定位为 Agent 主导的、证据可追溯的静态网表审查器。输入同一设计快照的 pstxnet.dat、pstxprt.dat、pstchip.dat；给定 datasheet 可以随任务提供，也可以预先放入受限资料库。对用户是一次提交 DAT，不要求每次重新上传资料，也不要求提供问题列表。

输出只包含经过原始连接核对、适用资料核对及独立复核后成立的错误。没有充分证据的候选不进入错误报告；内部保留简短覆盖和执行记录。无确认发现不是整板安全认证。模型复核不构成形式证明，实际精确率、召回率需要真实数据验收。

不默认引入未知固件、外部负载/电压、PCB、网上补料、外部 SPICE 模型或测量数据。不以网名推导电压，不改原始连接。自进化保留后续方案，初版不运行。

## 2. 推荐形态

Deep Agents Python SDK + 三类 Agent 角色 + 五个本地适配 Skills + 精确 DAT 工具 + 按需 datasheet 检索/页面阅读 + 隔离计算 + 逐发现复核。

三类角色：
- 主审查 Agent：看全板、维护任务清单、分配调查、处理跨块关系、归并最终发现。
- 调查 Agent：围绕实际器件/网络执行调查，可跨越初始任务边界，可组合技能、补读资料、调用计算。
- 复核 Agent：在新上下文中重新检查候选涉及的原始连接、原文和条件，确认、反驳或保留未确定状态。

这不是三个串行的大服务，也不是每种芯片配一个 Agent。初版建议调查并发 3、复核并发 1；只是可调整的起始配置，不是准确率结论。各角色可先使用同一个经过工具调用和图像输入冒烟测试的主模型，以隔离上下文实现独立复核；不同模型只是后续可选对照。

资料阅读默认由调查/复核 Agent 调工具执行，不再固定增加 Reader、Extractor、Assembler、Judge 等多个模型环节。复杂文档反复成为瓶颈后，再考虑独立文档专家。

## 3. Harness 选型与配置

首选 langchain-ai/deepagents 的 Python SDK，不同时接入 DeepSeek Harness、Hermes 或另一套调度框架。选择理由是可复用自定义工具、按需 Skills、隔离子任务、多模态工具结果和运行状态能力。

采用本地应用进程；轻量任务队列、运行目录和本地检查点即可。复用已有检索器和模型客户端，必要时只做框架适配。初版不依赖 LangSmith 云服务、图数据库、独立向量数据库服务、Celery、复杂工作流 DSL 或大型插件市场。

开启：显式任务清单、调查与复核角色、Skills、上下文卸载、工具记录、本地恢复。
关闭：通用无限递归委派、自动联网补资料、任意宿主机 shell、自动修改 Skills/长期经验、默认人工逐步审批。

关键接线细节：
- 自定义子 Agent 需要显式配置 tools、skills 和来源读取能力；不能假定主 Agent 的 Skills 自动继承。
- 新上下文不等于拥有独立事实来源。复核必须读原资料，而非只看调查摘要；也不需要继承调查的完整思考过程。
- 工具的大结果写文件，给模型摘要和可继续读取的地址；分页和局部结果标明范围，不悄悄丢失对象。
- 原始输入和技能目录只读。框架文件权限不自动覆盖自定义工具或计算执行器，后两者自己限制可访问目录和网络。
- 数值脚本在无外网、无密钥、只读输入的隔离运行环境执行，只写本次临时目录。不要把隐藏 shell 工具当作没有 shell 权限。
- 锁定完成项目冒烟测试的依赖版本，再升级；不把在线最新版本直接当作已验收版本。

DeepSeek Harness 保留为交互式插件平台需求出现后的备选，而非初版第二套底座。官方当前仍标记为 developer preview 并说明存在兼容性变化。

## 4. 正向执行通路

### 4.1 DAT 接入：生成精确事实，不生成电气结论

解析三份 DAT，建立 Component–Pin–Net 数据和原文记录定位。保留原始网名、位号、物理脚号、库声明、器件属性与可取得的装配状态。已在 pstchip 中声明但没有网络连接的脚也保留。

特别区分：导线同网、经器件存在结构路径、经某种模式导通。查询到一条跨器件路径并不自动等于短接或等电位。COPPER、零欧姆、分流器、开关的解释依赖输入中的实际定义，不把任意二端器件当导线。

保留库脚名与厂家物理脚定义两套信息，冲突可以是检查对象；不为使电路合理而修改映射。NC、DNP、NO/NC 接点以及同名网络不能只凭字面合并解释。导出器的特殊语义只能由已核验的方言规则支持。

局部属性不能理解时，保留原始值，相关检查继续读取原文或跳过。只有连接事实整体无法可靠读取时才结束运行并说明输入/执行失败；这不是板上电气错误。

### 4.2 全板任务规划：先按对象覆盖，再按功能关系深化

任务种子从完整器件、引脚、网络清单生成，而不是只从异常检测器或正常功能模板生成。

所有 IC、分立有源器件、连接器和有端子用途的特殊无源器件分配调查归属；普通无源器件通常随关联器件/网络一起检查，不逐个生成独立 Agent。无法分类的器件仍归入通用局部调查，不从清单消失。

同型号的资料读取结果可以复用，但不同实例的接线结论不可直接复用。

保留两个观察方向：
1. 器件/引脚：当前每组物理脚如何连接，是否违反适用要求。
2. 网络/跨块关系：网络两端、供电/反馈/采样/使能链是否存在冲突或遗漏。

主 Agent 可拆分、合并和追加任务。初始局部范围不是两跳硬边界；公共地和电源网络可以用完整成员索引提供，不让所有任务膨胀成全板全文。

只维护简短任务状态：已调查、仍待调查、因具体输入不足而跳过。它用于补漏和恢复，不是第二套合规审批系统。

### 4.3 调查：实际连接与 datasheet 双向核对

每个调查按需要交替进行连接查询、身份绑定、资料阅读和计算，不强制先完成一颗芯片的全部参数提取。

对已绑定型号，先浏览与本次使用相关的引脚定义、工作条件、使用要求、功能模式等章节，再针对疑点深读。不能只围绕最初怀疑的一项检索，否则可能遗漏未想到的要求。

应用图中的 R1/R2 是功能角色，不是本板同名位号。参考应用的一种接法不自动成为强制要求；必须区分规定、建议、典型值和绝对最大值。

### 4.4 资料入口：受限文档检索 + 原页阅读

复用现有 PDF 页文字/图像读取与证据组装，增加按确切型号/封装/资料版本限定的检索。首次构建低成本页面文字和章节索引；不必把每页都交给模型预抽取。

基线检索用精确词/章节词加 BM25 类词项排序；已有向量检索可作为第二路复用，不要求重建。检索返回页号、命中区和章节，模型再读原页与必要邻页/脚注/引用页。表格和引脚图的视觉读取初版就应可用。

常见路径：定位页面 → 读原页 → 补表头/脚注/条件 → 与实际接法关联。不是固定 top-k 摘要直接产出电气结论。

查不到不等于不存在。遇到“没有内部上拉”“资料未给例外”等否定结论，要核对相应章节/适当范围；材料仍不足则不判定。

保留文档原文缓存和解释缓存，但后者不能覆盖前者。缓存键包含资料快照和实际适用身份；本板使用结论还要区分实例和连接。

沿用当前 reader_prompt 的“有可定位知识就返回、缺字段不阻断其他条目”。不硬继承“一次首读、唯一补读轮”作为新 Agent 的通用上限：有新章节、新图像或新依赖时可继续；同一视图重复读取走缓存，无新增信息的循环停止或换调查方向。

### 4.5 按需计算：局部推导，不以完整整板建模为前提

初版提供 Python/SymPy/NumPy 计算能力，支持公式代入、单位换算、已知参数的范围检查和局部静态线性关系。Agent 可以形成短计算脚本，保存输入、表达式和结果供复核重跑。

计算是否执行正确，与方程是否代表真实电路是两件事。模型关系、使用模式、边界和每个输入都要有依据。额外支路不能为了套公式而丢掉；未知负载不能当零。

只在需要的地方建局部方程。没有足够资料时不补造完整器件模型，也不把正常模式失效后的理想输出继续传播。标称结果、可能越限、可实现越限和必然越限不是同一个结论；Monte Carlo 未发现正常样本也不是确定性证明。

### 4.6 候选与独立复核

调查输出轻量候选：对象、问题陈述、实际连接依据、适用要求及页码、必要条件、计算记录（有计算时）。不要求所有候选都有规则 ID、完整 min/typ/max 或全部器件参数。

复核 Agent 在新上下文中执行：
- 核对实际物理脚和连接，不只重复库语义。
- 核对确切资料、型号、封装和适用模式。
- 核对“要求”是否真的被违反，是否存在相关例外或合法替代。
- 涉及数值时，重跑关键计算并检查模型输入。

复核不是多数投票，也不是“无限寻找所有可能反例”。明确要求加明确违反即可确认；仅有影响该结论的实际歧义需要补查。

结果为 confirmed、refuted、undetermined；工具执行失败另外记录为执行状态，不当作电气判断。资料不足仅影响该候选。复核可以缩小结论，例如确认“违反连接要求”，而不声称“必然烧毁”。

已经确认的问题不必等所有其他任务完成才具备报告资格。主 Agent 不得把未确定候选直接改成 confirmed；结论实质变更后针对该条补核，不重新跑全板。

### 4.7 收尾与报告

主 Agent 检查尚未调查的对象和跨任务关系，按实际遗漏补查，不机械执行整板第二轮重复审查。用对象、违反要求和实际根因归并重复发现；共用电源但违反不同要求的发现不能只因同网就合并。

输出建议：
- errors.json：已确认发现的结构化集合。
- report.md：只列已确认错误、原始位置、资料依据、核查依据及有证据支持的修改方向。
- run_summary.json / 运行记录：任务范围、跳过/中断、模型与 Skill 版本、工具执行；作为内部调试材料，不把未知项转成警告。

若无发现，写“在本次已核查范围内，未发现可确认错误”。若运行中断，明确是未完成；不能伪装为完整检查通过。

## 5. 必要 Skills 的具体选用

以下本地名称是拟适配名称，不是已经存在的 DAT 成品或已安装包。

| 本地技能 | 上游来源 | 初版保留 | 初版修改/删减 |
|---|---|---|---|
| dat-netlist-investigation | Seeed-Studio/ai-skills，skills/schematic-analyzer/SKILL.md | overview/query、器件/引脚/网络调查、从结构回到语义再回查结构 | 替换为三 DAT 查询；取消 XML/KiCad/MCP/外部补料前置；不照搬按 NC 名称改变拓扑 |
| dat-datasheet-evidence | 同仓库 skills/ee-datasheet-master/SKILL.md；当前 reader_prompt | 参数定向查找、章节/表格/原页、来源和派生计算记录 | 限定给定资料库；缺资料写内部记录、不逐项要求用户补料；不固定六阶段全量提取 |
| dat-electrical-review | aklofas/kicad-happy 的 skills/kicad/SKILL.md 与 review/ 子模块 | 按实际器件用法对照资料、局部深审、根因归并 | 去掉 KiCad 专用脚本、强制 SPICE/EMC/PCB/热分析、整板资料覆盖阻断和经验参数回退 |
| dat-numerical-check | K-Dense-AI/scientific-agent-skills 的 skills/sympy/SKILL.md；按需参考 uncertainty-and-units | 方程求解、显式假设、代回验证；单位换算指导 | 只保留与静态电路有关的数学内容；通过隔离计算工具运行，不授予自由宿主机 shell；不把统计误差传播当最坏情况证明 |
| dat-finding-verification | 本项目编写；参考 kicad-happy 的证据定位机制 | 对象/资料/适用性/实际违反/计算的逐条核验 | 不沿用“存在文件或引用即已证明”的弱判定；不要求全局事实批准、固定规则 ID 或任意高置信分数 |

kicad-happy 的 skills/kicad/review/ 是内部子模块，不是独立可安装 Skill。保留少量上游程序性知识，经本项目工具适配后使用，不全量导入庞大技能包。

每个 Skill 包含：用途、输入、推荐调查方法、相关工具、输出示例和少量必要注意事项。name/description 和 SKILL.md 采用 Agent Skills 格式；来源、适配版本和许可说明保留在记录中。

主 Agent 持有短审查职责说明和可用技能索引；调查 Agent 可访问前四个技能；复核 Agent 可访问核查、资料、网表、计算技能，并按需读取电气参考内容。与本任务直接相关的核心技能在任务开始时明确加载，避免只依赖模型偶然触发。

电气技能的 references/ 初版覆盖以下方向，但不是硬判定规则库：
- 物理脚与多单元：MOSFET、二极管、单/双 BJT、开关及确切封装差异。
- 被动连接与端子用途：COPPER、零欧姆、CAP-EC、四端分流器、连接器边界。
- 供电与控制：LDO、eFuse、模块、转换器、供电/反馈/远端采样/使能/保护；多相/TLVR 仅调查输入支持的结构性与静态要求。
- 接口与复杂芯片静态使用：电平转换、MCU、主芯片、存储、时钟等资料明确的引脚、供电域和配置要求，不推断未知固件和高速时序效果。
- 模拟与监测：运放、比较器、DAC、采样/监测的实际连接和资料明确限制。

## 6. 工具接口建议

保留有限但完整的通用接口，不按器件类别无限扩展工具。

| 工具 | 用途 |
|---|---|
| board_overview | 器件/网络规模、属性统计和任务种子 |
| inspect_component | 物理脚、库声明、全部引脚状态、属性及实际相邻关系 |
| inspect_net | 网络成员、关联器件、原文定位；支持分页但不掩盖未返回范围 |
| trace_connections | 结构路径、支路及边界；不将结构可达等同于电气导通 |
| read_dat_source | 对有歧义的解析结果查看原始记录 |
| search_datasheet | 确切资料范围中的章节/文本/页面定位 |
| read_datasheet | 原页文字/图像、邻页、引用页和证据 ID |
| run_calculation | 在隔离环境内执行本次有依据的计算并保存重放记录 |

候选提交和最终报告可以用简单结构化输出处理，不必全部设计成独立网络服务。工具返回允许携带 raw/notes；身份、数值和条件不能为兼容输出而被静默修改。格式错误在适配层局部修复，不让整个调查从头重跑。

## 7. 升级条件：运行恢复与版本升级分开

以下是可观察的工程判断方向，不是自动升级系统，也不是未经实测的质量阈值。严重连接错误一经复现就修；召回、成本和稳定性问题先归因，再决定是否升级。

| 模块 | 可观察问题 | 本次任务的处理 | 反复出现后的升级方向 |
|---|---|---|---|
| DAT 解析 | 原始记录与物理脚/网络成员不一致，或某种导出格式稳定漏项 | 查原文，暂停受影响的结论；其他可信部分继续 | 补方言/实例化适配和原始记录回归，不用更强 LLM 修补错误拓扑 |
| 身份与封装 | 同系列多封装混用、双单元绑定反复失败 | 查确切封装表与属性；未确定处局部跳过 | 增加已核验的型号/封装绑定缓存与针对性适配，不按拓扑反推绑定 |
| 任务规划 | 已知错误对应对象/引脚从未被调查，或跨块连接无人负责 | 主 Agent 补任务 | 补任务种子与跨块扫描；先修覆盖，不先增加 Agent 类别 |
| 上下文/查询 | 完整网络存在的支路因分页、两跳截断或摘要丢失而被当成不存在 | 扩展查询，读完整成员或相关路径 | 改范围返回、依赖展开和分块方式；不先上图数据库 |
| 检索 | 人工已知证据页未返回，但直接提供该页后能够正确判断 | 改查询词、章节读、在给定文档内扩大范围 | 补混合召回、重排或目录树定位；用证据页覆盖对照验证收益 |
| 页面阅读 | 已取对页，仍错配表头、脚注、图中脚号 | 原页/局部高清视图与相关邻页重读 | 升级页面布局/表格解析或多模态阅读模型；必要时独立资料专家 |
| 计算 | 有足够输入但反复写错公式/漏支路 | 重查推导并重算 | 将重复可靠计算沉淀成工具；确有耦合需求再加局部 DC 求解，不建设整板通用模型前置 |
| 电气推理 | 原始连接和资料都齐全，仍把合法接法判错 | 复核纠正、保留反例 | 补 Skill 合法替代示例；对照更强主模型或复核模型，不改检索器背锅 |
| 复核过严 | 候选被拒只是缺不影响结论的字段，或检查器只看固定规则 ID | 针对实际断言重新复核/缩小断言 | 调整按断言的证据充分性，不整体降低核查要求 |
| 重复调查/输出 | 同型号反复读资料，同一根因反复报告 | 复用资料缓存、归并同根因 | 调整任务分组、缓存键和合并规则，不增加 Judge 层 |
| 模型适配 | 工具调用错格式、图片未传达、技能在子 Agent 中缺失 | 查看实际请求/响应，局部纠正 | 修客户端/工具 schema/角色接线，必要时更换模型；不先改电气方法 |
| 运行与恢复 | 长任务中断后重头运行、子任务失败牵连全板 | 保存完成任务和候选，继续可执行部分 | 加强本地检查点/调度；只有服务部署或多机需求成立再引入队列服务 |
| 资料能力边界 | 原资料没有必要状态、板外输入或要求 | 跳过该结论，其他检查继续 | 不以更多 Agent、更多检索或更强模型制造缺失事实；只有输入边界明确变化时才扩能力 |

不设置全板“资料覆盖 100% 才能开始”、每条知识审批、统一全部字段、固定只能补读一次、只能沿固定两跳、无规则 ID 不可报告等前置关卡。

运行中使用可调预算和无进展检测：重复相同查询不增加证据时提示改方向或结束该项；新的关键引用允许继续。总预算耗尽保留已核查结果及未完成状态，不用无限循环追求空想完备。

## 8. 初版实现顺序与验证

实现顺序不代表发布一个玩具版本；发布形态应包括上述完整闭环。

A. 先把真实 DAT 的器件/引脚/网络查询和来源定位做可靠。
B. 接给定资料的检索、原页图像、公式计算，使一次器件调查可以闭合。
C. 加主审查分工、整板任务归属和跨块补查。
D. 加独立复核、逐发现发布与根因归并。
E. 用真实板卡和人工确认标签反复运行，修复漏查与误报归因，再固定初版依赖和 Skills 版本。

测试至少覆盖：正常电路、单错误、多错误、合法替代、缺資料、跨块错误、工具失败和网名/位号置换。标签与运行输入隔离。

建议同一板卡运行至少三次观察波动。分别统计发现错误的准确率与召回、原始定位与证据正确性、任务遗漏、执行成功率、工具调用和成本。不能以“少报错使 precision 高”代替完成任务，也不能将合成结构测试的通过率宣称为真实板卡查错能力。

远端 DAT_check_2 当前是参考设计与内核，不是已完成生产 DAT 适配器；旧 DAT_Check 有 benchmark builder，但真实原件/独立标签不能据此假定已经接入。实施时复用经过实际核对的内容，不把目录存在当作功能已实现。

## 9. 自进化方案保留但不启用

保留后续方向：固定模型/基础能力 → 从真实运行与人工确认反馈归因 → 候选 Skills/检索策略修改 → 独立留出评测与回归 → 人工审阅发布。

初版只记录输入快照、模型与 Skills 版本、原始证据、工具动作/输出摘要、候选、复核结论和耗时成本。无需为将来的优化单建事件总线、训练平台或经验数据库，不收集隐藏思考作为必需资产。

GEPA、ACE、Evo-Harness 等候选方案仍保留在后续研究项；初版没有自动学习、在线改 Skill、改评分器或自动发布新版本。只有固定流程已经有稳定复现能力且存在独立标签/留出样本后，再讨论是否启用。
